# Учебник по SQL и PostgreSQL — хранилище

Obsidian-vault с учебником. Здесь правят тексты. Правила тренировки и работы с базами — в `CLAUDE.md` папки `SQL/`, этот файл только про устройство книги.

Эталон формата — папка `01-Реляционная модель и окружение/`. Когда инструкция и эталон расходятся, прав эталон. Состав книги — в `Оглавление.md`.

## Устройство

```
sql-book/
├── Оглавление.md                         ← части, главы, готовые уроки, план
├── 01-Реляционная модель и окружение/    ← папка = глава, NN-Название
│   ├── 1.1-Окружение.md                  ← файл = урок, <глава>.<урок>-Название
│   ├── img/                              ← рисунки только этой главы
│   └── TODO.md                           ← долги по главе
├── _templates/Урок.md                    ← болванка урока
└── .obsidian/snippets/textbook.css       ← вёрстка, завязана на разметку рисунков
```

- Части книги папками не делаются: они есть в `Оглавление.md` и в поле `book_part`.
- Двоеточия в имени файла нет: `1.4-Ограничения.md`, а заголовок «Ограничения: как база защищает данные».
- Номер урока входит в имя файла, поэтому имена уникальны на всю книгу и вики-ссылки не путаются.
- После добавления урока обновить `Оглавление.md`, навигацию во всех уроках главы и `lessons_total`.

## Скелет урока

Порядок обязателен. Болванка — `_templates/Урок.md`.

1. Frontmatter без обёртки в code fence.
2. `# Заголовок`, ровно как `title`.
3. Каллаут `[!abstract]`: `Глава · урок N из M` и одно обещание.
4. `## Где мы`, затем `---`.
5. Содержательные разделы `##`.
6. `---`, `## Где ломается`: сценарии с жирным началом, затем каллаут `[!example] Мост в .NET`.
7. `---`, `## Глубже / на синьора`.
8. `---`, `## Насколько важно для собесов`: список с 🔴 🟡 ⚪.
9. `---`, `## На собесе`: свёрнутые каллауты `[!question]-` с ответами `**RU:**` и `**EN:**`.
10. `---`, `## Промпт для агента практики`: строка `**Куда:**` и свёрнутый `[!example]- Промпт целиком` с блоком `text`.
11. `---`, каллаут `[!abstract] Навигация`.

Концовки из учебника по Linux («Как это ломается», задачи для самопроверки) здесь не нужны: их роль играют «Где ломается», «На собесе» и промпт практики.

## Код

- Блоки всегда с языком: `sql`, `bash`, `text`.
- После примера идёт абзац, который начинается с `**Что происходит.**`.
- Команды psql живут в блоках `sql`.
- Запросы и утверждения про `freight` сверять с живой базой, а не писать по памяти. Если проверить нельзя, ставить `**VERIFY**` и заносить в `TODO.md` главы.

## Рисунки

Ровно две строки подряд, без пустой между ними. CSS верстает подпись только у такой пары.

```markdown
![[1.2-freight-er.png]]
*Рис. 1.2.3. Подпись — законченное предложение с выводом.*
```

- Номер: `Рис. <урок>.<порядковый в уроке>`.
- Файл: `img/<урок>-<латиница-kebab-case>.png`.
- Вставка в Obsidian сама кладёт файл в `img/` рядом с уроком. Имя `Pasted image …` заменить сразу.
- Перед сдачей открыть картинку и убедиться, что она соответствует подписи.

## Ссылки

- Между готовыми уроками — вики-ссылки с алиасом, вплетённые в предложение: `[[1.4-Ограничения|урок 1.4]]`.
- На ненаписанные уроки и главы — обычным текстом, пока неизвестно имя файла. Такие места перечислены в `TODO.md`.
- Переименование из терминала ссылки не чинит, только из Obsidian.

## Язык

Обращение на «ты», кавычки-ёлочки, длинное тире с пробелами, короткие абзацы. Эмодзи только как метки приоритета.

## Работа с хранилищем

- Правки точечные. Готовый урок целиком ради стиля не переписывать.
- Ошибки в тексте сначала заносить в `TODO.md`, если не просили исправить.
- `workspace.json` не трогать: это состояние интерфейса.
- Файлы с кириллицей и пробелами в командах всегда кавычить.
