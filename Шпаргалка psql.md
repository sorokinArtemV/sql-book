# Шпаргалка psql

> [!abstract] Справочник
> Команды консоли Postgres на одной странице: как зайти, осмотреться, настроить вывод и выйти. Подробный разбор — в [[1.1-Окружение|уроке 1.1]].

---

## Зайти и выйти

```bash
docker exec -it pg18 psql -U postgres -d freight          # войти в базу freight
docker exec -it pg18 psql -U postgres -d freight -c 'SELECT count(*) FROM freight.shipments'   # один запрос и выйти
docker exec -i  pg18 psql -U postgres -d freight < query.sql   # выполнить файл с твоей машины
psql -h localhost -U postgres -d freight                   # с хоста, если psql установлен локально
```

|Команда|Что делает|
|---|---|
|`\q`|выйти; ещё можно `Ctrl+D` или просто `exit`|
|`\c freight`|переключиться на другую базу|
|`\conninfo`|куда я подключён: база, пользователь, PID backend-а|
|`\password`|сменить пароль текущего пользователя|

## Два вида команд

Обычный SQL заканчивается `;` и уходит на сервер. Пока точки с запятой нет, psql ждёт продолжения. Команды с `\` выполняет сам psql, `;` им не нужна.

Приглашение подсказывает, в каком ты состоянии:

|Приглашение|Что значит|
|---|---|
|`freight=#`|ждёт новую команду, ты суперпользователь (`>` — обычный)|
|`freight-#`|запрос не закончен, нужна `;`|
|`freight'#`|открыта кавычка `'`, закрой её|
|`freight(#`|открыта скобка|
|`freight*#`|ты внутри незавершённой транзакции|

Застрял в недописанном запросе: `\r` очищает буфер, `Ctrl+C` отменяет ввод или долгий запрос.

## Осмотреться в базе

|Команда|Что показывает|
|---|---|
|`\l`|все базы на сервере|
|`\dn`|схемы в текущей базе|
|`\dt freight.*`|таблицы схемы `freight`|
|`\dt+ freight.*`|то же с размерами|
|`\d shipments`|структура таблицы: колонки, типы, NULL, DEFAULT, индексы, CHECK, внешние ключи, `Referenced by`|
|`\d+ shipments`|то же плюс размер, хранение, комментарии|
|`\di`|индексы|
|`\dv`|представления|
|`\ds`|последовательности (`cities_id_seq`)|
|`\df`|функции; `\df *date*` — по шаблону|
|`\dT`|пользовательские типы и домены|
|`\dx`|установленные расширения|
|`\du`|роли и пользователи|
|`\dp shipments`|права доступа к таблице|
|`\dconfig work_mem`|значение настройки сервера; `\dconfig *mem*` — по шаблону|
|`\sf имя_функции`|исходный текст функции|
|`\sv имя_представления`|исходный текст представления|

Плюс в конце (`\dt+`, `\d+`, `\l+`) почти везде значит «подробнее». Шаблоны работают как `*` в файловой системе: `\dt freight.ship*`.

## Настроить вывод

|Команда|Что делает|
|---|---|
|`\x`|переключить расширенный вывод: каждая строка столбиком|
|`\x auto`|столбиком, только когда строка не влезает в экран|
|`\pset null '∅'`|показывать `NULL` значком, чтобы не путать с пустой строкой|
|`\timing`|показывать время выполнения каждого запроса|
|`\pset pager off`|не открывать длинный вывод в пейджере|

Если вывод открылся в пейджере (внизу `:` или `(END)`): пробел — дальше, `q` — выйти из просмотра и вернуться в psql.

## Выполнить запрос по-особому

Эти команды ставятся вместо `;` в конце запроса:

```sql
SELECT * FROM shipments WHERE id = 1 \gx                -- один раз выполнить в расширенном виде
SELECT status, count(*) FROM shipments GROUP BY 1 \watch 2   -- повторять каждые 2 секунды, Ctrl+C — стоп
SELECT * FROM shipments LIMIT 3 \gdesc                  -- не выполнять, а показать колонки и типы результата
```

**Что происходит.** `\gx` удобен для одной широкой строки, не переключая `\x` насовсем. `\watch` пригодится в главе 12, когда будешь смотреть на блокировки из второго окна. `\gdesc` отвечает на вопрос «какого типа получится колонка» без чтения данных.

## Редактор, файлы, история

|Команда|Что делает|
|---|---|
|`\e`|открыть последний запрос в редакторе; после сохранения он выполнится|
|`\p`|показать текущий буфер запроса|
|`\s`|история команд|
|`\i file.sql`|выполнить файл; путь — внутри контейнера|
|`\o result.txt`|писать вывод в файл; `\o` без аргумента — обратно на экран|
|`\copy shipments TO 'ship.csv' CSV HEADER`|выгрузить таблицу в CSV на стороне клиента|
|`\! ls`|выполнить команду оболочки, не выходя из psql|

Стрелки вверх и вниз листают историю, `Ctrl+R` ищет по ней, `Tab` дополняет имена таблиц, колонок и команд.

## Помощь

|Команда|Что делает|
|---|---|
|`\?`|все команды psql|
|`\h`|список SQL-команд|
|`\h ALTER TABLE`|синтаксис конкретной команды|
|`\errverbose`|подробности последней ошибки: код, файл и строка в исходниках Postgres|
|`\set ECHO_HIDDEN on`|показывать SQL, который psql шлёт в каталог на каждую `\d`|

## Частые SQL-команды для осмотра

```sql
SHOW search_path;                                   -- где ищутся таблицы без префикса
SET search_path TO freight, public;                 -- только на эту сессию
ALTER DATABASE freight SET search_path TO freight, public;   -- навсегда, после переподключения
SELECT version();                                   -- версия сервера
SELECT pg_size_pretty(pg_database_size('freight')); -- размер базы
SELECT pg_size_pretty(pg_total_relation_size('shipments'));  -- размер таблицы с индексами
SELECT pid, state, query FROM pg_stat_activity WHERE datname = 'freight';  -- кто сейчас подключён
```

**Что происходит.** Это обычные запросы, их можно комбинировать как любые другие. `pg_stat_activity` показывает соединения с базой. Твоё тоже там, его `pid` совпадает с `Backend PID` из `\conninfo`.

## Транзакции в консоли

```sql
BEGIN;
DELETE FROM customers WHERE id = 1950;
ROLLBACK;            -- отменить; COMMIT — сохранить
```

**Что происходит.** psql по умолчанию работает в режиме автокоммита: каждая команда сразу фиксируется. Внутри `BEGIN` изменения видны только тебе, пока не скажешь `COMMIT`. Для экспериментов на учебной базе это главный инструмент: пробуешь опасное и откатываешь. Если внутри транзакции случилась ошибка, дальше ничего не выполнится до `ROLLBACK`.
