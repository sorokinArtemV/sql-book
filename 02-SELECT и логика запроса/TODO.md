## Расхождения текста с базой и самим собой

- [ ] **`2.1-Логический порядок выполнения SELECT.md`** — «`GROUP BY shipments_cnt` (алиас)». Этот алиас объявлен как `count(*)`, и запрос падает: `aggregate functions are not allowed in GROUP BY`. **Фактическая ошибка.** Нужен пример с алиасом обычного выражения.
- [ ] **`2.3-Форма результата.md`** — «в эту же дату выставлено ещё несколько сотен счетов». В последнюю дату, 2026-07-09, выставлен один счёт, и запрос с `WITH TIES` возвращает одну строку. **Фактическая ошибка.** Сотни счетов в день бывают только раньше: медиана — 269.
- [ ] **`2.3-Форма результата.md`** — «Скорее всего вернутся строки с `id` 1, 2, 3, 4, 5» и «Postgres читает таблицу с начала файла». На самом деле вернулись 1062–1066. `shipments` занимает 9021 блок при пороге 4096, поэтому чтение продолжается с запомненной позиции. С `SET synchronize_seqscans = off` возвращаются 1, 2, 3. Второй сессии для этого не нужно, хотя пункт про синхронизированное сканирование говорит только про неё.
- [ ] **`2.5-Даты и время.md`** — «`x.CreatedAt.Date == day` в LINQ даст приведение колонки и зависимость от пояса сессии». EF Core 10 генерирует `date_trunc('day', s.created_at, 'UTC') = @day`. Функция над колонкой есть, а зависимости от сессии нет. **Фактическая ошибка.**
- [ ] **`2.3-Форма результата.md`** — «планировщик обычно строит для них одинаковый план». На 18.6 планы `DISTINCT` и `GROUP BY` различаются: `Unique` над `HashAggregate` и `Group` над `Partial HashAggregate`.
- [ ] **`2.2-NULL и трёхзначная логика.md`** — «Для уволенных водителей получается число». Все пять строк примера — работающие водители, и числа в выводе не видно.
- [ ] **`2.2-NULL и трёхзначная логика.md`** — «Автор базы (то есть я)». Голос автора черновика, в остальной книге такого нет.
- [ ] **`img/2.1-logical-pipeline.png`** — подпись «вычислить, дать алиасы» вылезает за границы блока.
